# v3 (FlowDB) Installation Experience — Same Package vs. Separate Package


| SDK | v2 (current, reference) | v3 — same package (pinned) | v3 — separate package Name |
|---|---|---|---|
| **Python** | `pip install "skyflow-python==2.0.0"` <br> `from skyflow import Skyflow` | `pip install "skyflow-python==3.0.0"` <br> `from skyflow import Skyflow` | `pip install skyflow-flowdb-python` <br> `from skyflow_flowdb import Skyflow` |
| **Node.js** | `npm install skyflow-node` <br> `import { Skyflow } from 'skyflow-node';` | `npm install skyflow-node@3.0.0` <br> `import { Skyflow } from 'skyflow-node';` | `npm install skyflow-flowdb-node` <br> `import { Skyflow } from 'skyflow-flowdb-node';` |
| **Go** | `go get github.com/skyflowapi/skyflow-go/v2` <br> `import "github.com/skyflowapi/skyflow-go/v2/client"` | `go get github.com/skyflowapi/skyflow-go/v3` <br> `import "github.com/skyflowapi/skyflow-go/v3/client"` | `go get github.com/skyflowapi/skyflow-flowdb-go` <br> `import "github.com/skyflowapi/skyflow-flowdb-go/client"` |
| **Java** | `implementation 'com.skyflow:skyflow-java:2.0.0'` <br> `import com.skyflow.Skyflow;` | `implementation 'com.skyflow:skyflow-java:3.0.0'` <br> `import com.skyflow.Skyflow;` | `implementation 'com.skyflow:skyflow-flowdb-java:1.0.0'` <br> `import com.skyflowflowdb.Skyflow;` |

> Separate-package names above (`skyflow-flowdb-python`, `skyflow-flowdb-node`, `skyflow-flowdb-go`, `skyflow-flowdb-java`) are illustrative — final naming is not yet decided.

> **Separate package requires a separate GitHub repository.** A different SDK name (e.g. `skyflow-flowdb-go`) maps to a different source repository — it cannot be served from the existing `skyflow-go` repo without additional redirect infrastructure.

> **Go note:** Go's module system requires a new import path for every major version. The import path in source code is always the explicit version — there is no silent v2/v3 mismatch. The "same package" column uses the `/v3` major-version suffix (standard Go convention); the "separate package" column uses a different module name entirely.

> **Java note:** v2 and v3 ship under the identical Maven coordinates (`com.skyflow:skyflow-java`) and identical package (`com.skyflow`) — only the `<version>` (or Gradle version string) changes. Unlike pip/npm, Gradle/Maven require an explicit version on every dependency declaration, so there's no "unpinned install" that silently resolves to latest; the risk is a stale/copy-pasted version string rather than a missing one.

## Trade-offs

| | Same package (pinned) | Separate package |
|---|---|---|
| Default install (no version specified) | Resolves to latest **v2** — silently wrong unless the user pins `==3.0.0` / `@3.0.0` / picks the `/v3` module path (Go) · N/A for Java (Gradle/Maven require an explicit version on every dependency) | Always resolves to the correct SDK — no pinning needed |
| Import path | Unchanged for Python/Node/Java · New major-version suffix for Go (`.../v3/client`) | New import path for all SDKs |
| Risk of accidental v2/v3 mismatch | Higher for Python/Node (easy to forget the version pin) · None for Go (import path is the pin) | Low — package/module name makes the choice explicit |
