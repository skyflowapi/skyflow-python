# v3 (FlowDB) Installation Experience — Same Package vs. Separate Package


| SDK | v2 (current, reference) | v3 — same package (pinned) | v3 — separate package |
|---|---|---|---|
| **Python** | `pip install "skyflow-python==2.0.0"` <br> `from skyflow import Skyflow` | `pip install "skyflow-python==3.0.0"` <br> `from skyflow import Skyflow` | `pip install skyflow-flowdb-python` <br> `from skyflow_flowdb import Skyflow` |
| **Node.js** | `npm install skyflow-node` <br> `import { Skyflow } from 'skyflow-node';` | `npm install skyflow-node@3.0.0` <br> `import { Skyflow } from 'skyflow-node';` | `npm install skyflow-flowdb-node` <br> `import { Skyflow } from 'skyflow-flowdb-node';` |

> Separate-package names above (`skyflow-flowdb-python`, `skyflow-flowdb-node`) are illustrative — final naming is not yet decided.

## Trade-offs

| | Same package (pinned) | Separate package |
|---|---|---|
| Default install (no version specified) | Resolves to latest **v2** — silently wrong unless the user pins `==3.0.0` / `@3.0.0` | Always resolves to the correct SDK — no pinning needed |
| Import path | Unchanged (`from skyflow import ...`) | New import path per package |
| Risk of accidental v2/v3 mismatch | Higher — easy to forget the version pin | Lower — package name makes the choice explicit |
